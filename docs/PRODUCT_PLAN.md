# Interview Studio v1 제품 기준 문서

## 1. 제품 정의

Interview Studio는 사용자의 이력·포트폴리오와 공개 회사/기술 자료를 바탕으로 한국어 모의 기술 면접을 진행하는 macOS·Windows 로컬 데스크톱 앱이다. 음성 질문, 마이크 답변, 답변 기반 꼬리 질문, 선택적 카메라 녹화, 전사와 최종 평가를 한 세션으로 제공한다.

- 제품명: `Interview Studio`
- 기술: Electron, React, TypeScript, pnpm, SQLite, Drizzle, XState
- 지원 OS: macOS 13 이상, Windows 10 22H2 이상
- LLM: 기기에 설치되고 로그인된 Codex·Claude·Gemini CLI
- 우선 언어: 한국어. 영어 기술 용어 혼용 지원
- 저장: 계정·서버·동기화 없이 운영체제 앱 데이터 폴더의 로컬 평문
- 배포: 개인용 unsigned alpha. 코드 서명, 스토어, 자동 업데이트 제외

새 면접의 자료 조사와 LLM 호출에는 인터넷 연결이 필요하다. 기존 기록 열람, 영상 재생과 내보내기는 오프라인에서도 가능하다.

## 2. v1 범위

### 포함

- 연습·실전 모드와 복수 지원 프로필
- 기술 면접과 회사 면접
- 공개 웹 리서치, 캐시, 출처가 고정된 세션 스냅샷
- OS TTS, 로컬 whisper.cpp 전사, 2D AI 면접관
- 720p WebM 녹화, 문항 타임라인, PDF·MP4 내보내기
- 결과 대시보드, 점수 추이, 약점 재연습 큐
- 완료 답변·녹화 조각 단위 저장과 강제 종료 복구

### 제외

- 직접 LLM API 연동, 로그인 사이트 수집, 클라우드 동기화
- 영어 면접, 텍스트 답변, 3D 아바타
- 영상 기반 표정·시선·태도 자동 평가

## 3. 개인정보와 프로필

첫 실행에서 다음 사실을 명확히 고지하고 동의를 받는다.

- 프로필 컨텍스트와 답변 전사는 선택한 CLI의 LLM 공급자에게 전달된다.
- 원본 문서, 음성, 카메라 영상은 LLM에 전달하지 않는다.
- 앱 데이터는 기기에 암호화하지 않은 평문으로 저장된다.

프로필의 최소 필드는 이름, 목표 직무, 경력 수준이다. PDF, DOCX, TXT, Markdown, PNG, JPG, 공개 HTTP(S) URL을 받을 수 있다. 원본 파일은 앱 관리 폴더로 복사한다. 이미지와 텍스트가 부족한 스캔 PDF는 로컬 한·영 OCR을 사용한다.

앱은 명시적으로 제공된 공개 URL의 본문을 직접 추출하고 스크립트 등 비본문을 제거한 뒤 LLM에 전달한다. LLM은 경력, 역할, 기술, 프로젝트, 성과, 문제 해결 사례를 출처와 연결한 구조화 Markdown 컨텍스트로 정리한다. 3.2만 자 이하 자료는 직접 정리하고, 더 큰 자료는 1.8만 자 이하 조각으로 나눠 자료별 요약을 원자적으로 저장한 다음 최종 병합한다. 같은 원문 해시의 중간 요약은 재생성 때 재사용한다. 컨텍스트는 즉시 사용하고 이후 사용자가 검토·수정·원본 재수집할 수 있다. 완성도가 60점 미만이면 부족한 항목과 질문 품질 저하 가능성을 표시하되 진행은 막지 않는다.

최초 온보딩은 선택한 CLI의 설치·인증·capability probe뿐 아니라 실제 구조화 호출까지 성공해야 완료한다. URL 직접 추출이 실패하면 선택한 CLI의 제한된 공개 웹 도구로 한 번 더 수집하며, 실패한 자료는 다른 자료의 성공 여부와 분리해 오류를 표시한다. LLM은 부족하거나 모호한 사용자 정보를 후속 질문으로 만들고, 사용자가 입력한 보완 답변을 로컬 원본으로 저장한 뒤 컨텍스트를 다시 생성한다. 비공개·로그인 전용 자료는 우회 수집하지 않고 파일 내보내기 또는 직접 설명을 요청한다.

## 4. 리서치

조사는 선택한 CLI의 웹 검색 기능만 사용하며 공개·비로그인 페이지로 제한한다. 웹 문서의 내용은 명령이 아닌 비신뢰 데이터로 처리한다. 각 출처에 제목, URL, 게시일, 수집일, 신뢰도와 요약을 저장한다.

- 회사 리서치 캐시: 7일
- 기술·GitHub 리서치 캐시: 30일
- 사용자는 새 세션에서 캐시 무시를 선택할 수 있다.
- 질문 생성에 사용된 결과는 세션에 별도 스냅샷으로 고정한다.

회사 특화 출처가 2개 미만이거나 최근 2년 내 출처가 하나도 없으면 공고·프로필에서 기술 스택을 추론하고 기술 면접으로 자동 전환한다. 기술 자료가 없으면 일반 지식으로 질문을 만들되 결과에 외부 근거 부재를 남긴다. 질문 간 주제 중복은 허용한다.

## 5. 세션 생성

기술 면접은 복수 기술 스택, 경력 수준, 집중 영역, 제외 영역, 본 질문 수를 입력한다. 회사 면접은 회사, 직무, 경력 수준과 전형 단계를 필수로 받고 공고 URL·파일·본문을 강하게 권장한다. 회사 질문은 공고·프로필·전형·조사 결과에 맞춰 기술, 프로젝트, 행동, 회사 적합성 비율을 자동으로 구성한다.

본 질문은 3~10개이며 기본값은 5개다. 전체 목록은 시작 전에 생성하고 세션에 고정하며 면접 중에는 숨긴다. 질문 하나는 하나의 주제 체인을 이룬다.

## 6. 면접 진행 규칙

각 질문을 음성으로 낭독한 뒤 녹음을 자동 시작한다. 답변 제한은 5분이며 60초와 10초 전에 경고한다. `답변 완료` 또는 시간 만료로 제출한다. 시간 만료 무응답은 0점이다.

질문 텍스트는 기본 숨김이며 사용자가 표시할 수 있다. 문항당 음성을 한 번 다시 들을 수 있고 재생 중 타이머는 멈춘다. 자막·재생 사용은 기록하지만 감점하지 않는다.

답변 뒤 LLM은 같은 주제의 꼬리 질문 또는 다음 본 질문을 선택한다. 꼬리 질문은 0~4개이며 충분한 답을 받았다고 판단하면 조기에 끝낸다.

연습 모드는 답변 뒤 전사를 수정하고 짧은 피드백을 확인하며 같은 답변을 한 번 다시 할 수 있다. 재답변은 꼬리 횟수에 포함하지 않고 같은 깊이에서 마지막 답변만 채점한다. 자유 일시정지를 지원한다.

실전 모드는 종료 전 전사·피드백·점수를 숨기고 수동 일시정지를 제공하지 않는다. 종료 뒤 전사를 수정해 재평가하면 원본 전사와 기존 점수를 덮어쓴다.

## 7. 상태와 장애 복구

XState 기준 상태는 다음과 같다.

`draft → researching → ready → device-check → asking → listening → transcribing → analyzing → completed/partial`

연습 중에는 `listening ↔ paused`가 추가된다. 각 완료 답변과 녹화 조각을 원자적으로 저장한다. 실전 중 앱·장치 장애가 발생하면 진행 중 답변을 폐기하고 마지막 완료 턴의 `다음/꼬리` 결정부터 같은 질문을 다시 시작한다. 복구 사실은 결과에 남긴다.

질문·꼬리 질문 등 일반 LLM 호출 제한은 60초이며 최초 호출 뒤 세 번 재시도한다. 총 네 번 실패하면 완료 구간을 보존하고 부분 종료한다. 프로필 컨텍스트 생성은 별도의 5분 전체 제한과 90초 비활성 제한을 사용한다. 큰 자료는 자료별 분할 요약과 최종 병합으로 처리하며, 실패한 조각은 동일 입력을 반복하지 않고 해당 원문 조각을 폴백으로 보존한다. CLI가 출력을 내면 비활성 제한을 갱신하고, 전체 제한은 진행 여부와 관계없이 유지한다. STT도 동일 오디오를 최대 네 번 처리한다. TTS 실패 시 타이머를 시작하지 않고 장치 재설정을 기다린다. 카메라가 끊겨도 음성 면접은 계속한다.

## 8. 음성·영상

OS 설치 음성을 탐색해 한국어 음성, 속도와 음높이를 설정하고 샘플을 재생한다. macOS는 `say`, Windows는 `System.Speech`로 오디오 파일을 만든 뒤 renderer에서 재생한다. 2D AI 면접관은 질문, 경청, 분석 상태와 입·눈 애니메이션을 표시한다.

마이크는 필수이고 카메라는 선택이다. 시작 전에 권한, 카메라 미리보기, TTS를 점검한다. STT는 앱 관리 모델(base, small, medium)과 로컬 whisper.cpp sidecar를 사용하며 small을 권장한다. 모델 다운로드 후 SHA-256을 계산하고 제공되는 해시가 있으면 대조한다.

카메라와 마이크는 720p 30fps WebM 조각으로 연속 기록한다. 결과 화면은 연속 영상과 답변별 타임라인 이동을 제공한다. FFmpeg로 별도 MP4 파일을 만들 수 있다.

## 9. 평가와 결과

문항별 본 질문과 꼬리 답변 전체를 하나의 체인으로 평가한다. 각 본 질문 체인은 동일 가중치다.

- 질문 이해·관련성: 25
- 근거·구체성: 25
- 논리·깊이: 25
- 전달 구조: 15
- 간결성·시간 관리: 10

결과에는 질문, 전사, 문항별 점수와 평가 축, 강점, 개선점, 개선 답변 방향, 출처와 타임코드를 표시한다. PDF는 이 내용을 포함하고 영상은 MP4로 별도 내보낸다. 영상 기반 자동 태도 평가는 하지 않는다.

완료 세션만 점수 추이와 약점 큐에 반영한다. 약점 주제를 선택하면 해당 주제가 채워진 새 기술 면접 화면으로 이동한다. 중도 종료는 기록과 영상만 보존한다.

## 10. 저장과 보존

SQLite와 Drizzle에는 프로필, 출처, 세션, 조사 스냅샷, 질문 계획, 턴, 평가, 집계와 설정을 저장한다. 원본, 모델, 오디오와 영상은 파일시스템에 둔다.

전체 세션은 최근 10개만 유지한다. 11번째 생성 전에 삭제될 제목과 삭제 범위를 고지한다. 삭제된 완료 세션에서는 회사명·원문 없이 주제와 평가 점수 집계만 유지한다. `모든 데이터 삭제`는 프로필, 원본, 세션, 영상, 캐시, 모델과 익명 집계까지 삭제한다.

진단 로그는 2MB 순환 파일이며 종료 코드, 지연, 장치, 권한과 파싱 오류 종류만 기록한다. 프롬프트, 문서 원문, 전사, 영상은 기록하지 않는다.

## 11. 보안 경계

Electron main, preload, renderer를 분리한다. `contextIsolation`과 renderer sandbox를 켜고 `nodeIntegration`은 끈다. 파일, DB, CLI, TTS, STT, FFmpeg는 타입이 지정되고 런타임 검증된 IPC만 통과한다. 사용자 선택 창에서 승인하지 않은 파일 경로와 앱 데이터 밖 미디어 접근을 거부한다.

CLI는 앱 전용 Git 저장소와 환경 변수 allowlist에서 실행한다. Finder·Explorer에서 실행한 앱도 Node 기반 CLI를 시작할 수 있도록 탐색된 CLI 디렉터리와 OS별 알려진 Node 설치 디렉터리만 자식 프로세스의 `PATH` 앞에 추가하며 사용자 셸 설정 파일은 읽지 않는다. 버전·인증 capability probe와 실제 호출은 동일한 정제 환경을 사용한다. Codex는 [OpenAI의 비대화형 실행 지침](https://learn.chatgpt.com/docs/non-interactive-mode)에 따라 ephemeral, read-only, no-approval, ignore-user-config/rules와 JSON Schema 출력을 사용한다. Claude는 print, no-session-persistence, safe, restricted, strict MCP와 명시 도구 목록을 사용한다. Gemini는 [공식 Plan Mode 정책](https://geminicli.com/docs/cli/plan-mode/)에 따라 sandbox, plan, 사용자 정책과 JSON 출력을 사용한다. 조사만 웹 도구를 허용하고 질문·꼬리·평가 호출에는 도구를 허용하지 않는다.

시작 시 설치 경로, 버전, 인증과 필수 플래그를 capability probe한다. 지원 판단은 특정 버전 번호가 아니라 필수 기능의 존재를 기준으로 한다.

## 12. 검증과 v1 합격 기준

자동 테스트는 XState 전이, 연습 재답변 선택, 100점 계산, 동일 체인 가중 평균, 무응답, 구조화 CLI 응답 wrapper, 10개 보존과 익명 집계를 다룬다. 별도 계약·보안·미디어·E2E 테스트는 실제 CLI와 두 운영체제에서 수행한다.

v1 합격 기준은 macOS 13+와 Windows 10 22H2+/11 실제 기기에서 프로필 생성부터 5개 본 질문, 동적 꼬리 질문, 음성 전사, 720p 녹화, 최종 평가, PDF·MP4 내보내기까지 데이터 손실 없이 완주하는 것이다.
